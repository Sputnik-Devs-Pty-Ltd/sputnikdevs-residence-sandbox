# Sputnik Devs Studio — Artificial Intelligence (AI) Usage Policy

**Target Audience:** Engineering Interns, Work-Integrated Learning (WIL) Students, Mentors  
**Scope:** Remote Internship Program  
**Effective Date:** 2026-10-01  

---

## 1. Executive Philosophy

At Sputnik Devs Studio, we recognize that Modern AI development tools (GitHub Copilot, ChatGPT, Claude, Gemini) are transforming the software engineering landscape. In production, we leverage AI to accelerate workflows and automate routine scaffolding.

However, **the primary goal of your internship is your personal growth into an autonomous, competent professional software engineer.** Relying on AI to write code you do not understand will actively prevent you from developing the mental models required to debug complex distributed systems.

> [!IMPORTANT]
> **Core Principle:**  
> AI must be used as an **accelerator of learning**, **never as a proxy for comprehension**. You are 100% accountable for every single line of code submitted under your Git authorship.

---

## 2. Permitted AI Usages (The "Amplifier" Mode)

Interns are encouraged to use AI tools for the following purposes:

1. **Explaining Conceptual Architecture:**
   * *Allowed:* Asking AI to explain the difference between `AsNoTracking()` and standard EF Core tracking, or how Dependency Injection scopes (`Scoped`, `Transient`, `Singleton`) operate in ASP.NET Core.
2. **Deconstructing Cryptic Error Messages:**
   * *Allowed:* Pasting a compiler error (e.g. `CS0234` or EF Core migration cycle warnings) to understand what the compiler is asking for.
3. **Drafting Syntax & Exploring LINQ Patterns:**
   * *Allowed:* Asking how to structure a complex LINQ `GroupJoin` or `SelectMany` query.
4. **Generating Test Data & Edge-Case Ideas:**
   * *Allowed:* Asking AI for realistic mock datasets or edge cases to test a room occupancy calculation (e.g., negative capacities, leap-year booking dates).
5. **Code Review Preparation:**
   * *Allowed:* Asking AI to review your diff for potential null reference exceptions before opening a PR.

---

## 3. Strictly Prohibited AI Usages (The "Autopilot" Trap)

The following practices violate engineering standards at Sputnik Devs Studio:

1. **Blind Copy-Pasting:**
   * Submitting code generated by an LLM without understanding every method, loop, and variable in the snippet.
2. **Prompt-and-Pray Architecture:**
   * Prompts like: *"Write me a full TicketsController with all CRUD operations and PostgreSQL database logic."*
3. **Data & Security Violations (Zero-Data-Leakage):**
   * **Never** paste database connection strings, server IPs, API keys, passwords, client information, or internal proprietary configurations into any third-party AI tool.
4. **Falsified Logbooks or Daily Standups:**
   * Generating synthetic or exaggerated daily work summaries using AI.

---

## 4. The "Defense Test" (Verification Mechanism)

To ensure academic and professional integrity, Sputnik Devs Studio enforces the **Defense Test**:

* During any code review or sprint demonstration, a mentor may select **any arbitrary line or block of code** from your PR and ask:
  1. *What does this line do?*
  2. *Why did you choose this data structure or LINQ operation over an alternative?*
  3. *What happens if this input is null, empty, or fails a database constraint?*
* **Evaluation Impact:**
  * If an intern can clearly articulate their code and defend their design decisions, they pass with distinction.
  * If an intern cannot explain how their code functions, the PR will be rejected immediately, and the intern will be required to re-implement the feature manually under mentor supervision.

---

## 5. Recommended AI Prompts for Active Learning

When using AI, use prompts that force you to think rather than prompts that spoon-feed you answers:

| ❌ Weak / Prohibited Prompt | ✅ Strong / Educational Prompt |
| :--- | :--- |
| *"Write a C# controller that deletes a student."* | *"Explain the HTTP standard differences between deleting an entity with soft-delete vs hard-delete in a RESTful API."* |
| *"Fix this code for me [pasted block]."* | *"Here is my code and here is the compiler warning. What underlying C# language rule am I violating here?"* |
| *"Write all my unit tests for MaintenanceTicket."* | *"What are 5 boundary conditions and edge cases I should test when validating maintenance ticket priority transitions?"* |

---

## 6. Summary Agreement

By participating in the Sputnik Devs Studio WIL / Internship program, you commit to treating AI as a pair programming mentor rather than an author. True engineering authority comes from understanding how systems work from first principles.
